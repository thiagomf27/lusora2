# Sound packs (D48)

A sound pack is the **menu** of sounds — the fourth personalization layer, and
the only one besides component packs that carries bytes. A theme picks cues from
it by name, the way `typography` picks packaged fonts by name.

```
contracts/sound-packs/<name>/
  manifest.json      # schema: contracts/schemas/sound_pack.schema.json
  sfx/*.mp3          # cues: one-shots and short loops
  beds/*.mp3         # background music, one per mood
```

Who decides what:

| Layer | Owns |
| --- | --- |
| **sound pack** | the files and the cue/bed vocabulary — a *menu* |
| **theme** (`sound`) | which cue for which event, mood→bed, the gains — a *sound* |
| **style pack** (`sfx`, `music`) | whether, how often, how long — a *rhythm* |
| **channel config** (`source_policy`) | the master on/off, the pack name, volumes |

The AI never sees any of it. Sound selection is consistent taste, which is
exactly what D8 removed from the model's job; the planner's only contribution is
`mood` per beat.

## The shipped packs

- **`doc-restrained`** — soft swoosh, soft chime, a page flip, a highlighter
  stroke, a typing loop. Dark, slow beds under a 1.4 kHz lowpass. Pairs with
  `doc-slow`, `explainer-medium`.
- **`punchy`** — brighter swoosh, a tight pop, the same page flip and
  highlighter, the same typing loop. Beds carry an octave shimmer and open to
  2.6 kHz. Pairs with `breakdown-blitz`, `listicle-fast`.

The two packs share three cues because the recordings behind them are one kit;
what still separates the packs is the swoosh and the transient — `woosh` against
`woosh_intense`, a soft chime against a camera click.

Both carry the same eight moods: `neutral, tense, somber, hopeful, urgent,
triumphant, reflective, playful`.

## The cues are recordings; the beds are still synthesized

**Cues** are real recorded audio, committed as the mp3s under each pack's
`sfx/`. `build.mjs` marks them `recorded: true`, which means it does not
generate them and will not overwrite them — it only probes each file for the
real duration the manifest needs. A recorded cue whose file has gone missing
fails the build loudly rather than being silently regenerated as a sine.

**Beds** are still generated by `build.mjs` from a formula — a snapped-frequency
chord stack per mood. They are deterministic, $0, offline, and reproducible, so
running the builder to re-cut the beds is safe with the recordings in place:

```bash
node contracts/sound-packs/build.mjs                 # both packs
node contracts/sound-packs/build.mjs doc-restrained  # one
```

The beds exist so the mix can be heard end to end without a network or a licence
question. **They are not recorded material and they do not sound like it** —
they are sine stacks, and they read as mood, not as music. Replacing them is the
next thing worth doing, and the procedure below is the same one the cues went
through.

### The licence is now `unknown`, and that is a placeholder too

It was `cc0` when every byte was synthesized here, which was verifiable. The
cues are now operator-supplied recordings whose provenance this repo cannot
assert, and the field is pack-wide (D33, D72) precisely so a channel's
anti-copyright rule is checkable — so it has to describe the weakest thing in
the pack. `unknown` is recorded into asset provenance rather than gating a
render, so nothing breaks; set it to the real licence once that is known, and
split the pack if the two halves ever disagree.

### Replacing a file with real audio

Nothing in the pipeline knows or cares which half a file came from. To swap one
in — a bed now, or a different cue later — drop the file in and edit
`manifest.json`; there are no code changes anywhere:

1. Put the file under `sfx/` or `beds/`.
2. Point the cue or bed at it and set `duration_s` to the **real** duration
   (`ffprobe -v error -show_entries format=duration -of default=nw=1:nk=1 file.mp3`).
   The compiler sizes one-shot items from this number; a wrong value produces a
   cue that ends early or overruns its window.
3. Check `license` still describes the weakest thing in the pack, and split the
   pack in two rather than loosening it — the field is pack-wide because that is
   what makes a channel's anti-copyright rule checkable (D33).
4. `node scripts/validate-schemas.mjs` — the CI gate checks the manifest against
   the schema, that `name` matches the folder, and that **every declared file
   exists**. A missing file fails here rather than surfacing as a render error on
   a real video days later.

`build.mjs` overwrites everything it generates, so a file you drop in has to be
marked `recorded: true` in that pack's `cues` table or the next rebuild will
replace your recording with a sine. Marking it also keeps the cue in the
manifest a rebuild writes — dropping it from `PACKS` instead would delete it.

### Notes on the synthesis, for whoever tunes it

- Bed frequencies are snapped to a whole number of cycles per 48 s
  (`snap()`), so a looping bed has no phase discontinuity at the seam. Off by a
  fraction of a hertz, inaudible; the click it removes is not.
- **Beds are normalized by loudness (-24 LUFS), cues by peak (-6 dBFS)** — the
  recorded cues were imported at that same ceiling, so this still describes the
  whole pack. It is not an inconsistency. EBU R128 integrated loudness of a 0.4 s transient is
  close to meaningless — the gating discards most of it, so `loudnorm` pushes a
  swoosh until it is clipping-hot while the measured number still reads quiet.
  What the ear judges in a one-shot is its peak. Peak-normalizing every cue to
  the same ceiling makes the theme's `gain.sfx` a predictable dB trim across the
  whole pack: at 0.28 each of these cues peaks at -17 dB, level with a typical
  narration peak.
- Beds run deliberately quiet because the ducking envelope is what sets their
  level in the mix — `music_duck` 0.16 puts a -24 LUFS bed at -40 LUFS, about
  18 dB under the voice, and `music_lift` 0.5 brings it to -30 LUFS in a gap.
  Headroom in the file matters more than loudness. If you replace the beds with
  material at a different level, retune those two theme tokens to match, or the
  music will either vanish or fight the narration.
- Each chord voice is doubled by a twin detuned by ~0.6-1.1 Hz. The slow beat
  between them is most of what stops a sine stack reading as a test tone.
- `lead_s` on a cue starts it *before* the visual it belongs to, so the
  transient lands on the entrance instead of beginning there. It is set per cue
  from where that recording's attack actually is: a swoosh is pulled back far
  enough to arrive rather than follow, a click barely at all.
